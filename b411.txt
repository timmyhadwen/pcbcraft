## What
Show library footprint checker results in the app: quality badge per part in Libraries settings and grouped `lib_*` findings in the Checks tab (same grouping pattern as ERC/DRC).

## Why
Follow-up to epic #344. The ### Standards comment on #344 describes UX beyond the generate/check commands; not required for #344 acceptance.

## How
Call `library.footprint.check` (or cache findings on upsert) from UI; reuse `Session::checks` grouping patterns in `a_newcomer_sees_findings_grouped_by_check`. Depends on #344 child 2.

## Acceptance
- e2e: imported bad footprint shows grouped library finding with plain fix hint.
- Tooltips on badge controls.

### Rules for whoever picks this up
- Branch off fork main (wdunn001/pcbcraft) and merge the latest fork main into your branch before your final push. Push the branch; do not open a PR.
- New code and PR text may not name other EDA tools.
- Typed engine commands with bounded validation; no unwrap/expect/panic anywhere, tests included.
- The GitHub Actions run on your pushed branch must be green; it is the proof.
- Every new control gets a tooltip; panels keep real margins and padding.
- End-to-end tests in crates/ui-egui are named like `a_newcomer_*` and must read like a story for someone who has never seen the app.
