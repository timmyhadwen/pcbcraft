## What
Part of #349 (text catalog). Move every user-visible string in the settings area of crates/ui-egui onto the catalog: the Settings page and Appearance, units, project fields, board setup fields, and their help text.

## Why
#349 landed the catalog crate (pcbcraft-text), the Language picker in Settings and the `t!("key")` accessor, and converted the app bar and the File, Edit, Settings and Help menus. The rest of the UI converts area by area so several agents can work without colliding in crates/ui-egui/src/lib.rs.

## How
- Read crates/text/strings/en.txt and the converted functions (header, file_menu, edit_menu, settings_menu, help_menu, language_menu in lib.rs) for the key naming: `area.thing` for the label, `area.thing.tip` for its tooltip, `{name}` placeholders for values, `.one`/`.other` for counts.
- Replace each literal in the area with `t!("key")` or `t!("key", name = value)`; add the English text to en.txt. Words stay identical, so existing a_newcomer_* stories keep passing.
- Add each converted function to crates/text/strings/converted-fns.txt (`<file> <fn>`). `cargo xtask strings check` and the test `no_user_visible_literal_outside_the_catalog` then fail if a literal comes back.
- Do not translate document content, net names, file paths or library part text. Engine refusal text stays English.
- Work after #349 is merged; one conflict:ui-egui-lib ticket at a time.

## Acceptance
- `cargo xtask strings check` is green and lists the new functions as converted.
- Every control in the area keeps its tooltip, now from a `.tip` key.
- The existing a_newcomer_* stories for the area pass unchanged.
