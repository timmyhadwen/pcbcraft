## What
Capture a screenshot of every page, tool, dialog and main workflow step of the desktop app, for the user guide and the website. Today `cargo xtask screenshots` captures a short fixed list of views (VIEWS in xtask/src/main.rs) by launching the app with `--capture`.

## Goals
- A catalog of named shots, each defined as a scripted state: which page, which sample project, what is selected, which dialog is open, which step of a workflow. Reuse the e2e story helpers (`tap_id`, `type_into`) so a shot is a short script, not a hand-made image.
- Shots are reproducible: the same commit gives the same images (fixed fonts, sample data, window size, no clock or random values on screen).
- Light and dark theme, at 1x and 2x scale.
- File names are stable and match the guide's image references; a check fails when the guide names an image the catalog does not make, or a shot is unused.
- Runs headless on .57 and in CI.

## Research questions
1. Headless capture options for this egui 0.36 app on Linux CI: the viewport screenshot command used now, offscreen wgpu, a software renderer, or the egui test harness's own rendering. Speed, fidelity and determinism of each.
2. How to keep images small (PNG optimisation, WebP) and how to diff them so unchanged shots don't churn the repo.
3. Where the images live: in the repo, in a release artifact, or built only for the site.
