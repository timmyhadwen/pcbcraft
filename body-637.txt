## What
Until a client has sent `initialize`, answer every method except `initialize` and `ping` with the error the server already uses for `tools/*` (-32002 "initialize the MCP session first"). Today only `tools/*` is gated.

## Why
Found by the #613 audit against the lifecycle page of revision 2025-11-25: before the initialize response the client should send nothing but pings. The gap is harmless today and becomes real when #614 adds resources and prompts.

## How
Base: fork/main at a0b7682. `crates/mcp/src/lib.rs`, function `serve`: the test `!initialized && method.is_some_and(|m| m.starts_with("tools/"))` becomes "not initialized and the method is neither `initialize` nor `ping` nor a notification". Notifications (no id) are still ignored without reply. The bridge (`start_bridge`) has no session state and is unchanged. #614's HTTP transport must apply the same rule per session; note it there.
