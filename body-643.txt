## What
The MCP server advertises `resources` and answers `resources/list`, `resources/read` and `resources/templates/list` for the design. Child 2 of #614. Works on stdio and, when it lands, over HTTP.

## Why
Resources make the design readable without calling a tool. Revision 2025-11-25, server/resources.

## How
Base: fork/main at a0b7682. `crates/mcp/src/lib.rs`, `handle_rpc`; put the code in a new `crates/mcp/src/resources.rs`.
- `initialize` result: capabilities gain `"resources":{"subscribe":false,"listChanged":false}`. This edits the same line as the prompts child; land one before the other and merge fork/main.
- Resources, scheme `pcbcraft://`, each with `name`, `title`, `mimeType`, `annotations` (`audience: ["user","assistant"]`, `priority`):
  - `pcbcraft://design` (application/json): same content as `inspect_design`.
  - `pcbcraft://commands` (application/json): same as `list_commands`.
  - `pcbcraft://checks` (application/json): the result of the `checks` tool, run when read. Correction to the research note, which says "last result": no last-result store exists on fork main, so reading runs the checks and edits nothing.
  - Template `pcbcraft://design/preview/{view}` with `view` of `schematic` or `pcb`: `image/png` as a base64 `blob`, from the same code as the `screenshot` tool.
- `resources/read` with an unknown uri: JSON-RPC error -32002 "Resource not found" with `data: {"uri": ...}`.
- Reads go through `hub.call_tool` so the active design (DocumentHub) is used and nothing is edited.
- Add a short section to `docs/mcp.md`.
